If your group runs on Meetup, the WR-Games Meetup integration keeps your events in sync without manual copy-paste. Once linked, Meetup events mirror into WR-Games automatically: your local community can browse them, get notified when their games are on the table, and RSVP without leaving WR-Games (depending on your mode).

## Linking Your Group to Meetup

<Steps>
  <Step title="Open Group Manage → Features">
    Go to your group, tap **Manage**, then open **Features** and find the **Meetup** card.
  </Step>
  <Step title="Enter Your Meetup Group URL">
    Paste your Meetup group’s URL (e.g. `meetup.com/your-group-name`). WR-Games validates the slug and begins the initial sync.
  </Step>
  <Step title="Choose Your RSVP Mode">
    Pick **Link-out** or **Side-by-side** (see below). You can change this later.
  </Step>
</Steps>

## RSVP Modes

The mode you choose determines where RSVPs live and what attendees see.

|  | Link-out | Side-by-side |
| :-- | :-- | :-- |
| Where RSVPs live | Meetup only | WR-Games \+ Meetup independently |
| CTA on future/published events | “RSVP on Meetup” | Native WR-Games RSVP |
| CTA on past/cancelled events | “View on Meetup” | “View on Meetup” |
| Attendee surface on event page | “Attending via Meetup” list only | Native list \+ “Attending via Meetup” list |
| The two lists reconcile? | N/A | No |

<Note>
  **“Attending via Meetup” appears in both modes.** In link-out, it is the only attendee surface: the native WR-Games attendees panel is hidden. In side-by-side, it shows read-only alongside the native list. Either way, the two lists never merge.
</Note>

**Which mode to choose:**

- **Link-out** if Meetup is your authoritative RSVP source and you don’t want headcount split across two platforms.
- **Side-by-side** if you want to capture WR-Games-native RSVPs from people who aren’t on Meetup, while still showing Meetup attendance alongside.

## Sync Cadence

Mirrored events update automatically on a regular schedule: an event's title, time, and description stay current on their own. A few changes don't come through automatically and need a manual **Refresh from Meetup** (below): a cancellation where the organizer leaves the event listed on Meetup, plus venue or cover changes made after the event first mirrored.

## Refresh From Meetup

The **Refresh from Meetup** button on the **Meetup Integration** card re-polls the Meetup feed immediately and re-enriches mirrors from the Meetup event page. Use it when you’ve updated something on Meetup and don’t want to wait for the next automatic sync.

- **Cooldown:** 60 seconds between refreshes.
- **Cover image:** Overwrites a Meetup-sourced cover with whatever is current on Meetup. If you’ve uploaded your own cover through WR-Games, it is never overwritten.
- **Venue, map, and cancel status** always refresh regardless of how they were last set.

## What You Can Edit on a Mirror

Meetup controls certain fields on mirrored events. Changes you make on WR-Games to those fields get overwritten on the next sync. Other fields are yours to set directly.

| Field | Who Controls It |
| :-- | :-- |
| Title | **Meetup**, syncs automatically every cycle |
| Date and time | **Meetup**, syncs automatically every cycle |
| Description | **Meetup**, syncs automatically every cycle |
| Location / venue | **Meetup**, re-enriched on every Refresh from Meetup |
| Event type | Fixed: always a **Custom Event** |
| Cover image | **You**, an upload through WR-Games is never overwritten by sync |
| Capacity | **You** (side-by-side mode only; in link-out, synced from Meetup) |
| RSVP settings | **You** (side-by-side mode only; in link-out, RSVP lives on Meetup) |
| Additional hosts | **You** (side-by-side mode only; in link-out, read-only) |
| Games / On the Table | **You**, unless auto-pin is on (below) |

### Can I change a Meetup event to an Open Game Night or Game Session?

You can set it up to work like either one. An event that comes from Meetup always stays a Custom Event, so **Change event type** doesn't appear on it, but a Custom Event can do what the other two types do. Edit the event and choose one under **Optional features**:

| If You Want It to Work Like… | Turn On |
| :-- | :-- |
| An Open Game Night, where attendees add the games they're bringing and play at tables | **Enable On the Table** |
| A Game Session, built around one game | **Pin to a specific game** |

It's one or the other: turning either on switches the other off.

## Auto-Pin a Game From a BGG Link

If you already put a BoardGameGeek link in your Meetup listings, WR-Games can read it and pin that game to the mirrored event for you. No extra step on Meetup, no editing the mirror afterwards.

Auto-pin starts on for every linked group. Turn it off on the review step when you import or claim a group, or any time at **Group Manage → Features**, on the **Meetup Integration** card. It's set per linked group, and it works in both link-out and side-by-side.

Once a game is pinned it shows on the event's **On the Table** tab, exactly like a game you pinned by hand. Mirrors open on Overview, so it's one tab across.

### When It Pins, and When It Doesn't

| Your Listing | What Happens |
| :-- | :-- |
| One BGG link | That game gets pinned |
| Two or more BGG links | Nothing is pinned. It won't guess which one you meant |
| The same link twice | Still counts as one, so it pins |
| A game we don't have yet | Nothing is pinned, and nothing is guessed from the web address |

<Note>
  Your own pin always wins. If you pin a game by hand, sync will never overwrite it, even if the listing later points at something else.
</Note>

<Warning>
  **Removing a pinned game is permanent.** Edit the event, clear the game, and it stays gone. Sync keeps running and the link is still sitting in your listing, but that game won't come back. If you want it again, pin it by hand.
</Warning>

Two more things worth knowing. If you change which game your listing links to _after_ a pin has already landed, the pin doesn't follow. Edit the event instead. And on a very long listing, a BGG link buried right at the bottom may not be seen at all, so if you want it picked up, put it somewhere reasonable in the body.

## Choose a Default Host for Synced Events

In side-by-side, your synced events need a host. You pick one when you switch to side-by-side, and the **Host** row on the Meetup Integration card shows who it is. That person is listed as host on new synced events and marked as going, so nobody has to RSVP on each one by hand.

Select **Change** to pick someone else. Any group member can be the host. Upcoming synced events led by the current host, and any with no host, move to the new one. Events where you set a different host by hand stay as they are.

If the host leaves the group, the card shows **Your Meetup Events Need a Host**. Events keep syncing with no host until you select **Pick a Host**. In link-out there's no Host row, because RSVPs live on Meetup.

## Auto-Cancel Meetup-Synced Events

When an event is cancelled or deleted on Meetup, WR-Games cancels its synced copy too and tells its guests. **Auto-Cancel Meetup-Synced Events** starts on. You'll find it at **Group Manage → Features**, on the Meetup Integration card, and on the review step when you import. Anyone who can manage the group's settings can change it.

It only ever touches events that came from Meetup. Events you create on WR-Games are never affected.

<Tabs>
  <Tab title="Auto-Cancel On">
    When Meetup cancels or removes an event, the synced copy is cancelled here and its guests are told.
  </Tab>
  <Tab title="Auto-Cancel Off">
    When Meetup cancels or removes an event, the copy stays live on WR-Games. Organizers get a notification, "\{event title\} was cancelled or removed on Meetup", so you can cancel it here if it isn't happening.
  </Tab>
</Tabs>

Turn it back on and any synced events already cancelled or deleted on Meetup are cancelled here at the next sync, and their guests are told.

A kept event still changes a little: its **Attending via Meetup** list empties once Meetup drops the event, and in link-out it still shows **RSVP on Meetup**.

## Defaults for Synced Events

Two settings on the Meetup Integration card decide how new synced events start out.

<Columns cols={2}>
  <Card title="Guests per RSVP on Synced Events" icon="user-plus">
    Off, or 1 to 10. New and unedited synced events allow that many guests per RSVP. Off leaves guests as they are. Starts off.
  </Card>

  <Card title="Attendee Limit from the Pinned Game" icon="users">
    Sets each synced event's attendee limit to its pinned game's max players. If the game has no max, no limit is set. If the pinned game changes, the limit follows it. Starts off.
  </Card>
</Columns>

<Check>
  **Your edits win.** Once you change the attendee limit, guests on or off, or guests per RSVP on a synced event, sync leaves that setting alone on that event.
</Check>

Turning a default off stops further changes. It doesn't undo what's already set. In link-out the defaults still apply, though RSVP settings stay locked on WR-Games. Raising a limit lets waitlisted members in, the same as when you edit an event.

## Sync Health

The **Meetup Integration** card shows the current health of your Meetup connection:

| Status | What It Means |
| :-- | :-- |
| Healthy | Syncing normally |
| Auth revoked | Meetup access was revoked, re-link to restore |
| Slug renamed | Your Meetup group URL changed. Update it under **Group Manage → Features** |

Other error states may appear if the feed is temporarily unreachable. Waiting for the next automatic sync or tapping **Refresh from Meetup** resolves most transient issues.

## If Your Meetup Group Can't Be Reached

If your Meetup group is deleted, goes private or stops responding, WR-Games keeps checking on it once a day.

After 3 days, syncing stops and everyone who can manage the group's settings gets a notification: **Meetup sync stopped**. Your group isn't hidden or deleted, and events you created on WR-Games aren't touched. Whether your synced events are cancelled or kept follows your Auto-Cancel setting. If the Meetup group comes back, syncing starts again on its own.

Check **Sync Health** on the Meetup Integration card to see where things stand.

## Unlinking

<Warning>
  Unlinking stops all future syncing. Before you confirm, WR-Games asks what to do with **upcoming** mirrored events. You can cancel them or leave them frozen as-is. Cancelling notifies native WR-Games RSVPs; Meetup attendees on the “Attending via Meetup” list are not emailed. Past mirrors are always retained.
</Warning>

Go to **Group Manage → Features** and select **Unlink From Meetup** on the Meetup Integration card.

## What Members See

Members don’t configure anything. Here’s how mirrored events appear to them.

**“via Meetup” badge**, shown on event cards and detail pages so it’s clear the event originated on Meetup.

**RSVPs and CTAs** depend on mode and event status:

- Future/published event in **link-out** → “RSVP on Meetup” opens Meetup directly.
- Future/published event in **side-by-side** → native WR-Games RSVP as normal.
- Past or cancelled event in either mode → “View on Meetup.”

**“Attending via Meetup” list**, shown on every mirror in both modes. It includes a last-synced timestamp and a note that guest counts may be understated (Meetup’s API doesn’t always surface full guest totals).

**Auto-cancel:** A mirror is cancelled when its event is cancelled or removed on Meetup, unless the group has turned Auto-Cancel off.

**Sync note:** Mirror detail pages display “Event details sync automatically from Meetup.” so members know edits happen on the Meetup side.
